## Summary

- **The dataset entry lives in ONE JSON file and is looked up by SET NAME, first-match file order.** `serpentrum/data/stacking_pi_stack.json:4-15` holds exactly one interaction `pi_stack_pd` (mode `pi_stack`, `distance_a 3.383`, `lateral_offset_a 1.231`, citation `janiak2000`, `applies_to.sets ["set_a"]`, status `APPROVED`). - **The full capture→place call chain is: engine event → pre-resolved skip taxonomy → placement.resolve → place_pickup → clash gate.** `'`stacked`' event emitted at `game_engine.py:718`; dispatched at `gui_game.py:684-716` into `_handle_stack_event` (`gui_game.py:847-1056`); record enrichment at `gui_game.py:919-924`; **skip taxonomy pre-resolved BEFORE any geometry** at `gui_game.py:937-941` via `placement.resolve_skip` (`placement.py:102-129`, fix G1); stackable path calls `placement.resolve` (`gui_game.py:959-963`, `placement.py:215-265`) which re-runs `interaction_for` (`placement.py:240`), computes the tail frame (`placement.py:132-157`), and calls `stacking.place_pickup` with `interaction['distance_a'] / interaction['lateral_offset_a']` (`placement.py:176-180`, `stacking.py:182-255`); clash gate `placement.gate` → `stacking.check_clash` (`placement.py:195-212,250-256`, `stacking.py:258-305`, wall leg retired — unbounded box, atom-clash only).
- **The canonical planar 6-ring eligibility extractor ALREADY exists and is exactly reusable:** `setloader._upload_stack_ring(record)` (`setloader.py:242-263`) = `molfile.ring_cycle(record)` (one canonical simple cycle ≤6 over the 2-core, `molfile.py:577+`, 2-core via `find_ring_atoms` `molfile.py:524`) gated on `len == 6` AND `stacking.ring_frame(record['coords'], candidate)` not raising (planarity tol `PLANARITY_TOL_A = 0.15`, `stacking.py:52`). Eligibility predicate for consent gating = `'stack_ring' in record` — the same key the renderer, spawner mirror, and pickup m16 already branch on (`gui_game.py:519,539,560-563,1135-1136`).
- **The consent-OFF byte-identical seam is now provable: gate everything on whether `'__upload__'` can find an entry through `interaction_for`.** If (and only if) consent is ON, an in-memory dataset overlay (a copy of the loaded dataset + one extra APPROVED generic interaction targeting `['__upload__']`) is what the capture path consumes. ## Answers to the scoped questions

**1. Entry location + full capture call chain.** Entry: the JSON file (map row 1). Chain: `game_engine.py:718` `('stacked', pickup)` → `gui_game.py:684-716` dispatch → `_handle_stack_event` `gui_game.py:847` → enrichment `:919-924` → pre-resolve `placement.resolve_skip` `:937` (`placement.py:102-129`) → `placement.resolve` `gui_game.py:959-963` (`placement.py:215-265`) → `interaction_for` re-lookup `placement.py:240` → `tail_frame` `placement.py:132-157` → `attempt_place` → `stacking.place_pickup` (`placement.py:176-180` → `stacking.py:182-255`) → `gate`/`check_clash` (`placement.py:250-256` → `stacking.py:258-305`) → placed: `engine.attach_segment` (`game_engine.py:749-766`) + viewer transform/rename (`gui_game.py:965-976`); non-placed: `engine.reject_pickup` (`gui_game.py:1002`, `game_engine.py:768-822`).

**2. A generic entry indistinguishable IN MECHANICS but distinct IN LABELING: same `distance_a 3.383` / `lateral_offset_a 1.231` (the approved encoding — no new values), `mode 'pi_stack'`, own `id` (e.g. `pi_stack_generic`), `name`/`explanation` carrying the "generic (illustrative geometry — user-approved)" wording (HUD renders both verbatim; recap groups on id via the stored `interaction_id`), `citation 'janiak2000'` (already in the shipped citations table), `applies_to.sets ['__upload__']`, `status 'APPROVED'` (passes the `shipped_interactions` membership gate at `placement.py:120-124`), `uncertainty_a null`.

**3.
