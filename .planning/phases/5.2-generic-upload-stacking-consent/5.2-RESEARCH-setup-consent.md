## Recommended control choice: **QCheckBox** (DRAFT — subject to feel-check approval)

| | QCheckBox (recommended) | QComboBox 2-item |
|---|---|---|
| Data shape fit | Binary consent maps 1:1 to `isChecked()` — the tab's only existing checkbox routes a bool-ish toggle with identical mechanics (`xtb_auto_check`, `gui_setup.py:115-116/265-268/313-323`) | Would abuse `currentData()` semantics: every existing combo carries a multi-value choice over a pure-schema constant (`KNOWN_SETS`/`BOX_PRESETS`/`SPEED_TIERS`/record ids) — binary data is not a combo shape in this codebase |
| House pattern | Matches a working, human-verify-approved (03-08 10/10) in-tab toggle including its `_loading`-guarded `setChecked` restore and immediate-surfacing `stateChanged` handler | No binary combo precedent exists anywhere in the repo |
| Wording capacity | Checkbox label can carry the full DRAFT consent sentence (one widget, word-wrapped layout) — e.g. `Allow generic π-stack placement for uploads (illustrative geometry — user-approved)` | Combo needs two item strings (`off` / `on (illustrative — user-approved)`) — the OFF state stays self-explanatory but offers no extra disclosure space |
| Restore/apply | `setChecked(bool)` + `_loading` guard — mirrors the xtb restore (313-323) exactly | `findData` + DEFAULTS fallback extra indirection (291-305) for two values — more code, no benefit |
| Extensibility | If later stacking modes appear, the checkbox can be promoted to a combo then | Zero cost now, but pays a small debt if modes multiply |

**Tradeoff honestly noted:** a 2-item combo is more self-documenting at a glance (explicit OFF shown) and scales to multiple future stacking modes — but the house idiom, the data shape, and the minimal-diff discipline all favor the checkbox. The ROADMAP allows both; recommend checkbox with a word-wrapped label, and a short sub-line QLabel (hessian-label pattern, `gui_setup.py:124-127`) under it for the disclosure sentence if the feel-check wants more text in-band.
