# Phase 5.3: Randomized Pickup Spawning — Research (spawn-policy core)

**Researched:** 2026-09-26
**Domain:** Pure pickup-spawn policy (`serpentrum/spawn.py`) for the PyMOL snake game
**Confidence:** HIGH (all findings read directly from shipped code + tests; no external sources needed — this is a self-contained pure-layer policy change)

## Summary

The "too close to the snake" complaint has a precise mechanical cause: `spawn.py`'s candidate generator is **head-relative** — every candidate sits on a 12 Å line segment 8.0 Å ahead of the head along the current heading (`LOOKAHEAD_A=8.0`, `LATERAL_MAX_A=±6.0`). In the default medium box (±55 Å, shrunk to ±51.5 → 103×103 Å ≈ 10,609 Å²) the spawnable set at any moment is a measure-zero 1-D segment that tracks the snake's nose, so every pickup materializes ~8–14 Å from the head (≈1.3–2.3 s of travel at the default 6.0 Å/s). The fix is a candidate-generator swap inside `PickupSpawner._spawn`: replace the lookahead+lateral draw with **seeded uniform sampling over the shrunk box**, rejection-sampled against the existing four clearance legs plus a new minimum head distance, keeping the seeded RNG, `MAX_DRAWS`, grid-scan fallback, and the entire demote/cooldown machinery untouched. The public API (`__init__`, `first`, `next_after`, `can_spawn`, `note_resolution`, `tick`, properties) can stay **signature-identical**, so `gui_game.py` needs zero wiring changes — which also sidesteps the ROADMAP-flagged Phase-6 shared-file ordering hazard (06-05/06-09 depend on 5.2 gui files).

**Primary recommendation:** Option (a) — seeded uniform-in-shrunk-box rejection sampling with a box-proportional minimum head distance (~0.35 × shrunk half-span, tunable constructor kwarg), retiring only `LOOKAHEAD_A` / `LATERAL_MAX_A` / `LATERAL_QUANTUM_A` and the lookahead base-point math.

## Current Spawn Machinery (precise)

All in `serpentrum/spawn.py` (413 lines, PURE — stdlib `math`/`zlib`/`random` only, python3.6 `%-formatting`, auto-classified PURE by `tools/check_purity.py`).

### Candidate generation (`_spawn`, lines 309–352)

1. Guardrails: empty order → `None` (310–311); cooldown active → `None` (312–316); unknown heading → `ValueError` (317–319).
2. Heading unit vector from private `_DIRS` mirror (109–114; deliberate decoupling from `game_engine.DIRS`); perpendicular `px,py = -uy, ux` (324).
3. **Base point** = `head + heading × LOOKAHEAD_A(8.0)` (327–328).
4. Up to `MAX_DRAWS=32` seeded draws (329–335): `lateral = _draw_lateral()` (354–357: `rng.uniform(-6.0, +6.0)` quantized to 0.1 Å → 121 discrete values), candidate = `base + perp × lateral`, validated by `_legal`.
5. **Grid-scan fallback** (336–352): deterministic scan of the shrunk box from `(x0+3.5, y0+3.5)` in `GRID_STEP_A=2.0` steps, **x-major / y-minor, first legal wins** — no RNG. On total failure → `None` with **no state advance** (same record + pid re-offered next call; `_issue` only runs on success, 403–413).

### Clearance gates (`_legal`, lines 359–401) — candidate rejected if ANY leg fails

1. Shrunk-box containment: `box_min + 3.5 ≤ c ≤ box_max − 3.5`, inclusive (`WALL_MARGIN_A=3.5`).
2. Head-centroid distance ≥ `HEAD_CLEARANCE_A=5.0`.
3. Every translated candidate atom ≥ `CHAIN_ATOM_CLEARANCE_A=3.0` from every chain atom (xy only; the full per-atom double loop).
4. Centroid ≥ `LIVE_PICKUP_CLEARANCE_A=6.0` from every live pickup centroid.

The REFUSE_WALL placement gate is **gone** (2026-09-20c owner directive) — only capture-time REFUSE_ATOM refuses exist; the wall margin here is placement hygiene, not a game rule.

### Seeded RNG & determinism contract

- `seed_from_setup(setup)` (117–129): `zlib.crc32` over sorted `'%s=%r'` items — **never `hash()`** (PYTHONHASHSEED per-process randomization would break GAME-07 restart determinism). Process-stable, cross-process-stable.
- Private `random.Random(seed)` per spawner (191) — never the global `random` module (`setup_logic.randomize_head` precedent). Two same-seed spawners → byte-identical `(record, pid, centroid)` sequences over the same call sequence.
- `build_pickup_seed(record, pid, centroid, atoms)` (132–153): engine pickup contract `{'id', 'molecule_id', 'centroid', 'atoms' (translated copy), 'atoms_n'}`; unknown keys carried through engine copies.

### Round-robin / demote / cooldown machinery (KEEP — untouched by randomization)

- Serve order = rotating records list; `_issue` pops front → appends back, pid `'pick_%04d'` serial (403–413).
- `note_resolution(molecule_id, refused)` (229–269): refused → demote record to back + streak++; streak ≥ pool size → `_cooldown_remaining = exhaust_cooldown_ticks`; placed/SKIP → streak reset; streak frozen while paused (no extend/refresh).
- `tick()` (271–288): one per 100 ms movement tick; returns `True` exactly on the resume edge (streak resets).
- `EXHAUST_COOLDOWN_TICKS=100` default (~10 s at 100 ms tick), tunable constructor kwarg (187). Since 2026-09-20c this fires only on genuine clash streaks — a pure safety net.

## Root Cause of "Too Close"

The generator is **head-anchored, not box-anchored**:

- Candidate set = one point `head + 8.0·heading` plus a ±6.0 Å perpendicular slider → a **12 Å line segment 8 Å ahead of the nose**. In the medium box that's a 1-D set inside a ~103×103 Å² plane — effectively zero explore.
- Because the segment re-anchors to the head on every resolution, spawns can never land more than `√(8² + 6²) = 10.0 Å` from the head (minus quantization), i.e. **all spawns live in a 10 Å bubble around the current nose regardless of box size** — on large ±85 the bubble is 6% of the box half-span; on small ±35 it's 29%.
- At the owner-finalized default speed (normal tier = 6.0 Å/s, setup_logic.py:58; 0.6 Å per 100 ms tick) a spawn is captured after **~13–17 ticks ≈ 1.3–1.7 s** of mostly straight travel — no steering decision required. Even the relaxed tier (3.0 Å/s) reaches it in ~3 s. Capture radius `PICKUP_RADIUS_A=3.0` (game_engine.py:108) makes the last approach forgiving.
- Lateral quantization (121 values) + 32 draws means the first legal draw wins quickly near center; the grid fallback (which **would** roam the box) essentially never fires in normal play because the bubble is almost always legal.
- Net effect: the box size the owner scaled up for cap-10 (2026-09-20: small ±35 / medium ±55 / large ±85) is **never actually used by pickups** — the player's map is big but the game happens within arm's reach of the snake. This exactly matches the owner feedback 2026-09-26.

## Randomization Options Compared

| | (a) Uniform in shrunk box **(RECOMMENDED)** | (b) Uniform XY + z constraints | (c) Zoned/quadrant anti-cluster |
|---|---|---|---|
| Candidate draw | `rng.uniform` per axis over `[box_min+3.5, box_max−3.5]` | same, plus z rules | seeded zone pick + in-zone uniform |
| z semantics | N/A — spawn plane is xy; z is display-only (`BOX_DISPLAY_Z`) | **Inapplicable**: there is no z degree of freedom in the spawn policy (centroid is 2-tuple; `_pickup_m16` places at z=0). Rejected as a non-question. | same xy plane |
| Constants retired | `LOOKAHEAD_A`, `LATERAL_MAX_A`, `LATERAL_QUANTUM_A`, `_draw_lateral`, base/perp math | same as (a) | same as (a), plus new zone constants/state |
| Constants kept | `WALL_MARGIN_A`, `HEAD_CLEARANCE_A`, `CHAIN_ATOM_CLEARANCE_A`, `LIVE_PICKUP_CLEARANCE_A`, `MAX_DRAWS`, `GRID_STEP_A`, `EXHAUST_COOLDOWN_TICKS`, `MAX_LIVE_PICKUPS` | identical | identical |
| New constants | `MIN_HEAD_SPAWN_DIST_A` or box-proportional min-dist (see Fairness) | — | zone grid size, anti-cluster radius |
| Determinism | same `random.Random(seed)` stream; 2 draws/attempt instead of 1 → same-seed sequences still byte-identical | — | same, but more stream consumption per attempt |
| Success probability (32 draws) | medium: excluded area (head disk r≈18 + chain ≈ few hundred–1500 Å² + 4×π·36 live) ≪ 10,609 Å² → per-draw ≥ ~75–85% → fallback essentially never; small box cap-10 worst fold ≈ 50% → 2⁻³² fallback rate | — | comparable, marginally better late-game |
| Grid fallback bias | unchanged (corner-biased: x-major from `(x0+3.5, y0+3.5)`) — see Risks for the seeded-offset refinement | — | fallback less reached, same bias when reached |
| API impact | **zero** if signatures kept (heading arg becomes position-neutral) | — | zero |
| Complexity / review surface | ~20-line diff in `_spawn` + constant block + docstring rewrite | — | noticeably more state and tests |
| Difficulty feel | uniform ⇒ mean head distance ≈ 0.5–0.7 × box span; every capture requires navigation | — | slightly more even spacing; diminishing returns |

**Recommendation: (a).** It is the minimal change that answers the owner complaint verbatim ("more random in the box"), preserves every pinned behavior the cooldown/demote family depends on, keeps determinism and the test harness shape, and needs no `gui_game.py`/engine touch. Option (c)'s anti-clustering buys little: `LIVE_PICKUP_CLEARANCE_A=6.0` already separates simultaneous pickups, and successive-pickup clustering under uniform sampling is a feature (varied challenge), not a bug.

## Fairness Constraints & Box Geometry

**Minimum head distance.** Current `HEAD_CLEARANCE_A=5.0` was sized to avoid spawn-on-nose, not to create gameplay distance. Under uniform sampling the *mean* distance is already large, but the *minimum* still needs a floor so an unlucky draw can't drop the next molecule at 5.1 Å (same "too simple" case, stochastically). Options:

- **Fixed constant** (e.g. `MIN_HEAD_SPAWN_DIST_A = 12.0–15.0`): simple, but insensitive to the 35/55/85 presets the owner deliberately scaled.
- **Box-proportional (recommended):** computed once in `__init__` from the shrunk half-span `h = (box_max − box_min)/2 − WALL_MARGIN_A` (small 31.5 / medium 51.5 / large 81.5): `min_dist = clamp(0.35 × h, HEAD_CLEARANCE_A, 0.8 × h)` → small ≈ 11.0, medium ≈ 18.0, large ≈ 28.5 Å. At 6.0 Å/s that's 1.8 / 3.0 / 4.8 s of minimum travel — enough to demand at least one turn typically, still trivially winnable at cap-10 (the whole box is the playfield; worst case is a far-corner spawn, ~87 Å diagonal on medium ≈ 15 s cruise).
  - The clamp upper bound matters: it guarantees a legal point exists even with the head anywhere (min_dist < span), and keeps the tiny custom test boxes (±6, ±2 in `test_spawn.py` exhaustion pins) behaving as today (min_dist folds to ≤ 0.8×h ≈ 0.5–2.0, so those boxes aren't accidentally made always-`None` — and where they should be `None`, they still are).
  - Expose as a constructor kwarg (`min_head_dist_a=None` → proportional default), mirroring the `exhaust_cooldown_ticks` tuning precedent, so tests can pin exact values and difficulty can be re-tuned without a policy edit.
- Keep `HEAD_CLEARANCE_A=5.0` as the absolute hard floor (capture-radius hygiene, `PICKUP_RADIUS_A=3.0`) whether or not the proportional value exceeds it — the min-dist gate subsumes it in practice but the floor documents intent.

**Where the box comes from:** `setup_logic.BOX_PRESETS[setup['box_preset']]` → `gui_game._build_engine` line 464 → constructor args. The spawner already receives it; **no new wiring** is needed to compute the shrunk geometry inside `spawn.py` (it already computes it in the fallback, lines 339–342 — factor that into a helper shared by the sampling loop and the fallback).

**z geometry:** none. The game plane is xy, `BOX_DISPLAY_Z=5.0` is display-only; pickups are edge-on π-stacks placed at z=0 by `_pickup_m16`. Any "uniform in 3-D" idea is out of scope — Research question 3(b) resolves as inapplicable.

## Degenerate Cases

1. **Chain nearly fills a small box (cap-10 on ±35):** shrunk area 63×63 ≈ 3,969 Å². Worst-case exclusion: head min-dist disk (π·11² ≈ 380) + chain-atom disks (3.0 Å + molecule half-extent ≈ 1.5–2.5 Å radius each, but heavy overlap along the ~36 Å backbone) + up to 4 live-pickup disks (π·6² ≈ 113 each). Realistic excluded fraction mid/late game ≈ 30–55% → per-draw success ≥ ~45% → 32 draws fail ≤ ~10⁻¹⁰. Uniform sampling **still succeeds within `MAX_DRAWS=32`**; genuinely saturated states degrade to the existing fallback → `None` → no-state-advance retry, exactly as pinned today (tests 510–539). No semantic change.
2. **Grid-fallback corner bias:** under the current lookahead policy the fallback almost never fires, so its x-major first-legal-wins bias (always the most-negative legal cell) was invisible. Under uniform sampling it stays rare but becomes *visible when it fires* (a late-game saturated small box would repeatedly spawn near the same corner). Cheap refinement: keep the fallback deterministic but start the scan at a **seeded offset** (e.g. begin the double loop at a seeded cell index and wrap), preserving byte-identical determinism while spreading forced spawns. Flag for the plan; not a blocker if deferred.
3. **First spawn vs mid-game:** currently `first(head=(0,0), 'right')` uses the same `_spawn` path with empty chain/live (`spawn.py` 290–292). Under uniform, the same policy applies naturally — the head starts at box center, min-dist applies, no special-casing needed. The heading argument becomes position-neutral; **keep it in the signature** (validation included) for zero-diff API compatibility, and update the docstring to say heading is accepted for compatibility/telemetry only. (Dropping it would force `gui_game.py` edits and drag 5.3 into the ROADMAP-flagged Phase-6 shared-file ordering — avoid.)
4. **Live-pickup ceiling 4 (`can_spawn`):** unchanged interplay — the ceiling gates the respawn attempt, not the sampling. With max 4 live centroids and 6.0 Å spacing, uniform draws rarely collide even on small.
5. **Cooldown family:** untouched. Refuse streaks come from capture-time REFUSE_ATOM (placement) resolutions, not from spawn `None`s; randomization changes neither the streak semantics nor the 100-tick resumable cooldown. The biphenyl 1.87 Å REFUSE_ATOM demonstrator (2026-09-20: "never fix it") is a capture-path behavior, unaffected by spawn policy.
6. **Tiny/degenerate boxes:** the proportional min-dist must clamp to the shrunk half-span (see Fairness) so custom micro-boxes in tests keep their pinned `None`-or-not behavior instead of becoming accidentally-unspawnable.

## Risks & Open Questions

1. **Determinism re-pin cost:** the RNG stream consumption pattern changes (2 draws/candidate vs 1), so any test or smoke pinning exact centroids for a known seed must be re-pinned. Contained to `tests/test_spawn.py` + any smoke asserting spawn coordinates (`smoke/08_stack_place_smoke.py` SPAWNOFFS — verify during planning whether it pins absolute spawn offsets or only viewer-transform algebra).
2. **Grid-fallback corner clustering** (visible only under uniform policy on saturated small boxes): seeded scan offset recommended; can be deferred to a follow-up task within the phase without blocking the core swap.
3. **Owner-tunable difficulty:** the right min-dist factor (0.35 proposed) is a play-feel number — plan should expose it as a kwarg and pin a default, with a note that owner feel-check may retune it (precedent: 5.1 speed tiers retuned after feel-check, 2026-09-25).
4. **Phase-6 file ordering:** keep the diff inside `spawn.py` + `test_spawn.py`; if any `gui_game.py` edit becomes tempting (e.g. dropping the heading arg), don't — ROADMAP notes 06-05/06-09 carry `depends_on: ["5.2-09"]` on shared gui files.
5. **Open question (LOW stakes):** should successive spawns get a (weaker) min-distance from the *previous* spawn in addition to live pickups? Live-pickup 6.0 Å already covers simultaneous ones; cross-resolution clustering is acceptable variance. Default: no — note in plan for owner discretion.
6. **No external-source risk:** this phase is a self-contained pure-policy change; all behavior is in-repo. The only "state of the art" that matters is the repo's own pinned contracts (GAME-07 restart determinism, 2026-09-19b/c/d owner directives), all verified in code above. No Context7/webfetch applicable.
