## Summary

`serpentrum/spawn.py` is the ONLY file with behavior that Phase 5.3's randomization changes; its test coverage lives almost entirely in `tests/test_spawn.py` (25 tests, 9 classes), which pins the seeded lookahead+lateral policy in specific places. Most of the file is **position-independent** (cycle order, pids, MAX_LIVE, demote/cooldown, exhaustion fallback, build_pickup_seed) and will survive a candidate-generation rewrite untouched; exactly **4 tests across 2 classes pin the lookahead/lateral geometry** and must be rewritten (table below). All other spawn touchpoints (`test_phase5_integration` s8, `test_phase51_integration`, `test_engine_speed` seed pins, `test_stack_parallelism`, `test_hud_content` cooldown DBG) pin seed/determinism/contract behavior that a randomized-but-seeded policy still satisfies.

The gates will automatically cover everything: Gate 1 py_compiles spawn.py + any new test file, Gate 2 re-checks spawn.py's PURE classification (default-strict; nothing to allowlist), Gate 3's scoped discovery picks up any new `tests/test_*.py` automatically. The required smokes (07/08 use pickups) build pickup scenes at **hard-coded centroids and never call PickupSpawner**, so randomized spawns carry **zero smoke risk**; the randomized policy is a game-feel change whose human verdict belongs in a live-feel checkpoint (5.1-06/5.2-09 precedent), not in smokes.

One correction to the task brief: **gui_game.py is GUI-class, not BRIDGE**, in `tools/check_purity.py` (allowlist = `pymol.Qt` only, any level; any other pymol*/pmg_tk anywhere is a violation). It imports pure modules freely (`from serpentrum import ...` is not a banned root), so Phase 5.3 wiring changes in gui_game.py are safe as long as no pymol.cmd/pmg_tk imports are added there.

**Primary recommendation:** Model the phase on 5.1-01's TDD shape — RED-rewrite the 4 geometry-pinning tests in `test_spawn.py` (same file, same classes), add new randomization pins there, and KEEP the seed/cooldown/contract pins untouched; no new integration file needed unless the engine+spawn chain is re-proven, in which case mirror `test_phase5_integration.py`'s s8 pattern.

## Conventions

- **File/name:** `tests/test_<topic>.py`, classes `Test<Group>(unittest.TestCase)`; discovery command is literally pinned in file docstrings: `python3.6 -m unittest discover -s tests -p "test_*.py" -v` (do NOT add `-t .` — fails on py3.6 with a non-package start dir). Single file: swap the `-p` pattern.
- **Header:** every test file starts `sys.path.insert(0, os.path.dirname(os.path.dirname(os.path.abspath(__file__))))` with `# noqa: E402` on the serpentrum imports. **NO `__init__.py` in tests/** (gate 1 hard rule). Tests never import each other (module-local helper copies).
- **Fixtures:** prefer REAL shipped data — `setloader.load_demo_set(stacking_path=setloader.default_stacking_path())` in `setUpClass`, `assert errors == []`; synthetic origin-centered dummy atoms (`_dummy_atoms`, 6 C atoms on a 1.4 Å ring) when the clearance math doesn't need real SDF geometry. `tests/fixtures/` holds molfile/xtb data dirs, no spawn fixtures.
- **Determinism assertion style:** build two spawners with the same explicit integer seed → compare sequences of `(record['id'], pid, centroid)` shapes with `assertEqual` (float equality is fine — same RNG stream). Different-seed divergence asserted with `assertNotEqual` on a sequence (never a single draw). Cross-process stability pins use a real `subprocess.Popen` child (`sys.executable -c ...`).
- **Float tolerance:** `TOL = 1e-9` / `DELTA = 1e-9` module constants; clearance asserts use `assertGreaterEqual(dist, LIMIT - TOL)`.
- **Override-hooks for tests:** tunable ctor kwargs with pinned defaults used for fast state-machine drives (`exhaust_cooldown_ticks=2/3/4`). A 5.3 randomization knob (e.g. a candidate-count or distribution parameter) should follow this pattern: default pinned by a constant-equal test, ctor override used in the behavioral pins.
- **unittest only** (no pytest anywhere in the repo); plain `assert` inside test-file private helpers is house-accepted (`_paused_spawner` precedent), `self.assert*` inside test methods.
- House style: the test-file module docstring enumerates the pin groups mirroring the plan's behavior cases; rewrite it with the tests (05-03 precedent).

## python3.6 Constraints

Verified against `spawn.py`, all of `serpentrum/`, and all of `tests/`:

- **No f-strings anywhere** (grep for `f'`/`f"` literals: ZERO hits in `serpentrum/*.py` and `tests/*.py`); house convention is explicitly **%-formatting** ("python3.6 syntax only (%-formatting, no f-strings)" — spawn.py docstring). Note: 3.6 *supports* f-strings, but the repo convention bans them — new code must use `'... %s ...' % x`.
- **No dataclasses, no walrus** — explicit docstring pins ("no dataclasses/walrus"); walrus couldn't compile on 3.6 anyway (gate 1 py_compile would catch it).
- **No `typing`** imports anywhere (grep-verified); plain functions/classes with `object` bases.
- **RNG pattern (pinned, do not deviate):** a PRIVATE `random.Random(seed)` instance per spawner — "NEVER the global random module" (`setup_logic.randomize_head` precedent, restated in spawn.py docstring; pinned by `test_phase5_integration` s8). 3.6-safe `random` APIs in use: `rng.uniform(a, b)`; `round(x / q) * q` quantization.
- **Seeding (pinned):** `zlib.crc32` over the canonical sorted `'%s=%r' % (k, v)` string, NEVER `hash()` (PYTHONHASHSEED per-process randomization would break GAME-07 restart determinism); cross-process stability pinned by a subprocess child test.
- Docstrings carry **dated policy lineage** (e.g. "2026-09-20c fix G1 ...") — 5.3 edits should extend, not delete, that lineage style.
- Reference SYMBOLS not line numbers in plans/tests context (5.1-01 plan convention).
