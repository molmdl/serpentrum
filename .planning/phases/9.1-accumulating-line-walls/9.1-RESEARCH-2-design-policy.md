### (a) Accumulate-vs-cap semantics

**Options:**

| Option | Description | Through repo principles |
|---|---|---|

| A2 Cap-then-stop-spawning (**recommended**) | walls add per capture until N live; at N, further captures spawn mols but no new walls; the set persists unchanged for the rest of the run | Honors the owner wording verbatim ("walls PERSIST/ACCUMULATE… more eaten mols = more in-box walls" — persistence for the whole set, growth bounded); deliberate echo of the repo's own ceiling pattern `MAX_LIVE_PICKUPS = 4` (`spawn.py:107`, the can_spawn gate — the wall policy gains the identical shape); determinism trivial (the gate is a pure function of the accumulated count); no eviction bookkeeping; the spawner's existing exhaustion semantics degrade naturally ("None ⇒ keep the previous wall", `wall.py:227-229` becomes "None ⇒ keep the previous SET"). |
| A3 Cap-then-replace-oldest (rolling) | at N, each new wall evicts the oldest | Re-introduces a replace-per-capture contract — exactly the contract the owner asked to remove ("walls that persist… instead of being replaced per spawn", 09-09-SUMMARY:155); needs eviction order + index recycling + delete-oldest wiring in the seam; a wall vanishing mid-run silently is a *new* surprise class the Phase-9 records never blessed. REJECT (available as owner override if the feel-check asks for late-game churn). |

**Fencing question ("can the box become unplayably fenced?") — honest analysis.** With A2 the accumulated set is bounded at N, and every later wall still passes all Phase-9 legs at its own spawn: L1 box-face inset (each end roundable — the Phase-9 constructive guarantee "With one-at-a-time walls (C4) a convex box can NEVER be split into disconnected regions: both ends are always roundable", `09-RESEARCH-engine-policy.md` §2.3 L1/:117 — note this exact sentence no longer holds for a SET, see (d)), L3 head launch clearance 8.0 Å (a wall can never appear on the head's imminent path), L2/L4 mol clearances, plus (d)'s L5 wall-vs-wall separation and the cap. **There is no formal connectivity proof** that a SET of legal walls cannot pen the head into a pocket — a graph-analysis check would be hand-rolled geometry with no repo precedent, against the "fairness by construction" grain. The residual risk is bounded three ways: (i) L5 keeps walls mutually separated so dense wall clusters cannot form; (ii) the cap (N=5 default) bounds total wall length well under Phase 9's rejected anchor on every preset (see (b) table); (iii) even a trapped loss is the shipped crash outcome — snake still completes → spectra ("Crashed snake still proceeds to spectra", `PROJECT.md` Key Decisions; GAME-05 class). The owner feel-check step "roam the box at cap — steering room" is the backstop (Phase-9 precedent: fairness constants are feel-check drafts by design).

**Recommended default: A2 cap-then-stop**, cap enforced inside `WallSpawner.next_wall` (see (g)) returning None with **zero draws consumed** — the exact shape of the degenerate-box guard (docstring: "A degenerate box (shrunk interval empty on either axis) returns None IMMEDIATELY, consuming no draws", `wall.py:36-38`; the code guard at `:236-239`; pinned by RNG-state audit `tests/test_wall.py:338-350`). The fraction-based length makes the footprint **span-symmetric** — every preset sits at the same 1.85× ratio at the default cap, and the whole set stays under half of the crowding level Phase 9's arithmetic rejected on the *smallest* box. **Naming precedent:** the repo's live-object ceiling is `MAX_LIVE_PICKUPS = 4` — "live-pickup ceiling (can_spawn gate)" (`spawn.py:107`). The wall analog in wall.py's single table:

**Recommended default: `WALL_MAX_LIVE_WALLS = 5`** in the `wall.py` constants table (`serpentrum/wall.py:64-74` — the single tunable block), owner-retune grid **3 / 5 / 8** (the D-WALL-* triplet-options feel-row pattern, 09-RESEARCH §3). ### (d) Wall-vs-wall clearance (NEW leg L5)

**Why NEW:** Phase 9 spawned exactly one wall at a time so a candidate never faced another wall ("one live wall at a time, the spawn seam's replace-per-spawn contract", `game_engine.py:894`). Accumulation breaks that — and Phase 9's own constructive fairness sentence ("a convex box can NEVER be split into disconnected regions: *both ends are always roundable*" for ONE wall, 09-RESEARCH :117) silently stops being a proof about the arena once walls can meet/nest.

**Options:**

| Option | Through repo principles |
|---|---|
| D1 No constraint | Two near-coincident walls render as one thick double-line; two parallel walls `g` apart leave a head corridor of exactly `g − 2·2.0` Å — a visually inviting but impassable gap (`g ≤ 4.0` ⇒ zero usable width). Unfair-by-geometry and *new*; the repo's fairness principle is fair-by-construction, not fair-by-hope. REJECT. |
| D2 Min center-distance between wall centers | Cheap but geometrically wrong: two long crossing walls have distant centers and a 0 Å intersection; D2 would admit an X-crossing and near-touching T-junctions. REJECT. |
| D3 **True segment-to-segment min clearance, new constant (recommended)** | The exact 2D distance family already in the module: the min segment-segment distance is `min` over the four point↔other-segment distances *plus* a proper-crossing test (crossing ⇒ distance 0 ⇒ rejected); every piece builds on `_point_segment_distance_sq` (`wall.py:90-111`, the identical clamped-projection helper the ENGINE keeps its own copy of — "one name per margin" discipline preserved: a new clearance, not a reuse of the death radius). |

**Value arithmetic (the corridor math, mirroring the shipped wall.py:65-67 comment):** two parallel walls `g` apart leave the head a usable corridor of `g − 2×2.0` (halo 2.0 each side, STRICT `<`). The shipped usability standard is the face corridor 3.0 Å (= margin 6.0 − boundary 1.0 − halo 2.0), which the owner approved at the 09-09 feel-check. Exact parity with that standard is `g = 7.0`.

**Recommended default: `WALL_WALL_CLEARANCE_A = 8.0`** (naming gradient: `WALL_MOL_CLEARANCE_A` / `WALL_LIVE_CLEARANCE_A` / `WALL_WALL_CLEARANCE_A`, `wall.py:70-72` extend as a family; the `_A` suffix discipline — Å distances vs dimensionless fractions). Rationale: usable between-wall corridor = 4.0 Å — at least as navigable as the shipped face corridors (compensating for the harder judgment of threading between two red lines vs face-to-wall), and numerically the same 8.0 family as the owner-retuned head launch clearance `WALL_HEAD_CLEARANCE_A = 8.0` (`wall.py:68-69`) — one sentence encodes the fairness axiom: *every wall keeps 8 Å from the head at launch and 8 Å from every other wall, always*. Owner-retune grid **6.0 / 8.0 / 12.0** (usable 2.0 / 4.0 / 8.0; 6.0 = tighter than face corridors, say-the-word).

**SRP_DEBUG audit surface:** extend `hud_logic.debug_wall_trace` (`hud_logic.py:443-461`) with ONE conditional suffix field `wwgap=%.4f` (the new wall's min clearance to the accumulated set), exactly the shape of the existing optional `' tick=%d'` suffix (`hud_logic.py:459-460`); the mandatory prefix and the owner-mandate `gap=` field stay byte-stable. The exact-format pin family (TestWallDebugTrace, `tests/test_hud_content.py:962+`) takes a same-commit coupled-pin addition for the wwgap branch — a Phase-9-owned file, sanctioned by the roadmap's "Phase-9 pin … updates" (ROADMAP:354). This makes the wall-vs-wall leg live-auditable exactly like `gap=` was at 09-09 step 3 ("the `DBG wall spawn ... gap=` line shows gap ≥ 3.0 … across several captures — PASS", 09-09-SUMMARY:141-143).

**Honest new-surface flag — NEW mol vs OLD walls (not decidable inside the four legs).** The four legs bind each wall to the mol set *at that wall's spawn*. With persistence, a LATER mol (spawned by the untouched 5.3 pickup policy, which knows nothing of walls — `spawn.py` legs are box-margin/head/chain/centroid only, `09-RESEARCH-engine-policy.md` §1.3) can land on/near an EXISTING accumulated wall. spawn.py cannot learn walls (byte-identical contract). Analysis: **no mol is ever un-capturable** — a capture position outside the wall halo always exists because `PICKUP_RADIUS_A = 3.0` (inclusive capture, `game_engine.py:668`) strictly exceeds the `WALL_COLLISION_RADIUS_A = 2.0` (STRICT crash) strip: points ≥ 2.0 Å from the wall and ≤ 3.0 Å from the mol centroid exist for any wall/mol offset (constructive, per-geometry). Class precedent: lethal-adjacent pickups already exist against the box boundary (a 4-phase-shipped, owner-approved env class — mols routinely spawn near faces). Recommended handling: **accept as environment-class** (visible hazard, capturable by construction) + pin the axiom as a derived one-liner (`PICKUP_RADIUS_A > WALL_COLLISION_RADIUS_A`, the 5.1-06 derivation habit) + a dedicated feel-check row ("capture a mol that spawned near an accumulated wall"). Owner escalation if it feels unfair live: a controller-side mol re-roll would be Game-07-legal (cross-version identity not owed, §4) but violates the seam-minimality grain — record-and-defer, decide at the feel-check.
