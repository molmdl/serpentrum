## Summary

- **Speed today = TWO constants multiplied:** the engine owns `SPEED_A_PER_S = 3.0` (Å/s, `serpentrum/game_engine.py:78`, consumed at `game_engine.py:640-641` as `head += heading * SPEED_A_PER_S * dt`); the GUI owns the cadence `TICK_DT = 0.1` and `TICK_INTERVAL_MS = 100` (`serpentrum/gui_game.py:88-89`, QTimer built at `gui_game.py:276-278`). Product = 0.3 Å/tick. There is no other speed source.
- **The setup-dict `'speed'` key already exists end-to-end in the pure schema but is NEVER consumed by the engine.** `setup_logic.DEFAULTS['speed'] = 3.0` (`setup_logic.py:58`), `validate()` enforces number > 0 (`setup_logic.py:203-205`), `save_setup`/`load_setup` round-trip it (`setup_logic.py:227-268`), and `gui_setup.collect_state` preserves it as a non-widget key (`gui_setup.py:230-233`). `gui_game._build_engine` passes only box/cap/budget to `GameEngine(...)` (`gui_game.py:475-480`) — speed is a dead key today. **Phase 5.1 is mostly "wire a key that already exists," not schema surgery.**
- **The engine has NO speed constructor kwarg today** (`game_engine.py:247-249`), but the codebase has the exact precedent for adding one: 02-10 extended the signature with keyword args with safe defaults (cited in `game_engine.py:251-254`), and `spawn.PickupSpawner.__init__(..., exhaust_cooldown_ticks=EXHAUST_COOLDOWN_TICKS)` (`spawn.py:186-187`) is the shipped constructor-kwarg-tunable precedent. Adding `speed_a_per_s=SPEED_A_PER_S` is mechanically identical and keeps every existing test green.
- **The module constant `SPEED_A_PER_S` must REMAIN at 3.0**: it is directly test-pinned (`tests/test_engine_core.py:87` `assertEqual(game_engine.SPEED_A_PER_S, 3.0)`) and the movement/collision test suites DERIVE their expected step from it (`tests/test_engine_rules.py:39`, `tests/test_engine_tail_follow.py:53`, `tests/test_engine_win_desync.py:42`). Make it the default value of the new kwarg, not a replacement lookup.
- **Calibrated constants are step-size-safe across 0.2–0.6 Å/tick.** All collision/capture checks are POSITION-based at the post-move position (not swept/tunnel-prone bands): `BODY_COLLISION_RADIUS_A 2.0` (kill tube 4 Å wide, `game_engine.py:102,668-683`), `PICKUP_RADIUS_A 3.0` (capture tube 6 Å wide, `game_engine.py:106,688-696`), `BOUNDARY_MARGIN_A 1.0` (half-plane condition beyond the wall — no tunneling possible, `game_engine.py:654-665`). Largest step 0.6 Å ≤ 15% of the widest tube → no step can skip over any kill zone.
- **Tick-count mechanics scale cleanly with a step-size knob:** the rigid sweep stays `TURN_TICKS = 6` ticks at ±15°/tick (`game_engine.py:85-86`, viewer delta derived per tick at `gui_game.py:800`) and the spawn exhaust cooldown `EXHAUST_COOLDOWN_TICKS = 100` ticks (`spawn.py:99`, clocked by one `spawner.tick()` per movement tick at `gui_game.py:654-655`). With a step-size knob both keep their wall-clock duration (~0.6 s sweep, ~10 s cooldown) at every tier — cooldown wall time does NOT change (the phase-context worry applies only to a tick-interval knob).
- **The gameplay distance side effects are real but by-design difficulty**: turn cost per sweep = 6 ticks × step (0.6 s of forward travel: 1.2 Å relaxed → 3.6 Å expert); distance to cross medium box (±55 Å, `setup_logic.py:92`) = 110 Å / speed (≈55 s → ≈18 s); fresh-pickup reaction window ≈ `LOOKAHEAD_A` 8.0 Å / speed (≈4.0 s → ≈1.3 s, `spawn.py:87,327-328`). All feel-check items, none need code.
- **Restart keeps the selection automatically** — no wiring needed beyond the engine injection: `_on_restart` re-reads `self._anchor.setup` and re-runs `begin_game(setup)` (`gui_game.py:1222-1236`), which re-runs `_build_engine(setup)` (`gui_game.py:374,425-481`). Whatever `_build_engine` reads is what Restart replays — the spawn seed even derives from the whole setup dict via crc32 (`spawn.py:117-129`), so a speed change also re-seeds spawns deterministically.
- **Save/Load persistence of speed is ALREADY FREE** (round-trips through `save_setup`/`load_setup` today); the Save/Load *buttons* are Phase 8 GUI (`gui.py:79-80` reserved empty row; `.planning/phases/03-*/03-RESEARCH-setup-ui.md:236-237`) — criterion 3 of ROADMAP 5.1 is verifiable via the pure round-trip only in this phase. Backcompat caveat: `load_setup` checks schema_version only and validate() errors on a MISSING speed key (`setup_logic.py:203-205` via `.get` → None) — but every file ever saved by this codebase already contains `speed` (shipped since Phase 2, `02-07-SUMMARY`), so true backcompat risk is nil if the numeric key stays.
- **Recommended knob: (a) per-instance step speed in Å/s on the engine at fixed 100 ms / dt=0.1** — timer untouched, `TICK_DT` untouched, all tick-count mechanics keep wall-clock identity, GAME-08 trivially true (one constant instance attribute per run), and the 04-09-recorded "tick cadence = potential future knob" note stays orthogonal (cadence was deliberately NOT coupled to speed; `04-09-SUMMARY.md:34,184`).

## Injection points (how a setup value reaches the engine)

1. **Pure engine (knob):** add `speed_a_per_s=SPEED_A_PER_S` to `GameEngine.__init__` and `reset` (`game_engine.py:247-262`), store `self.speed_a_per_s`, use it at `:640-641` in place of the module constant. Precedent: 02-10's "extend with keyword args with safe defaults" (`:251-254`) and `spawn.PickupSpawner(exhaust_cooldown_ticks=...)` (`spawn.py:186-187,200`).
2. **GUI injection:** `gui_game._build_engine` (`gui_game.py:475-480`) passes `speed_a_per_s=setup.get('speed', 3.0)` (or default-filled). This is the ONLY call site constructing engines in production (test files construct their own).
3. **Setup UI:** add a named-tier combo in `gui_setup._build_widgets` + `_build_layout` (GUI class), wire into `collect_state` (`gui_setup.py:225-254`) and `apply_state` (`:256-298`) following the box-combo pattern (`:105-108,272-275`). Tier NAME is a UI label; the stored value stays numeric Å/s so `'speed': 3.0` schema, validation, and persistence are untouched.
4. **Start path (unchanged):** Setup Start → `_on_apply` (`gui_setup.py:410-551`) → `start_requested(setup)` (`:562-563`) → `PluginDialog._on_start_requested` (`gui.py:84-94`) → `begin_game(setup)` (`gui_game.py:347`) → `_build_engine` — speed riding the setup dict the whole way, no new signal plumbing.

## Restart / pause / teardown notes

- **Restart:** `_on_restart` (`gui_game.py:1222-1236`) pulls `self._anchor.setup` and re-runs `begin_game`, which runs `_teardown_round` first (`:367`) then `_build_engine(setup)` (`:374`). "Restart keeps the speed selection" is AUTOMATIC once `_build_engine` reads the key; the anchor's setup is the same dict Apply/Start wrote (`gui_setup.py:549-550`).
- **Spawn determinism on Restart:** `seed_from_setup(setup)` crc32s the entire dict (`spawn.py:117-129`, consumed `gui_game.py:465`) — changing speed changes the seed, so each tier gets its own deterministic spawn sequence. Same-tier Restart reproduces identical spawns (GAME-07 intact).
- **Pause/resume:** engine flag flip only (`game_engine.py:719-730`); timers stop (`gui_game.py:1183-1184`); nothing speed-dependent. Cooldown clock freezes with the timers (`gui_game.py:648-655` comment).
- **Teardown:** `_teardown_round` (`gui_game.py:1313-1361`) touches timers/epoch/input/camera/pickups only — zero speed assumptions.
- **Camera/viewer:** `move_chain_delta` (`pymol_bridge.py:179`) and `sweep_chain` (`pymol_bridge.py:329`) take caller deltas; camera lock/unlock are view-state only. No Å magnitudes hardcoded in the GUI movement path beyond the tick delta itself.
- **Mid-run edit safety:** the tier combo lives on the Setup tab while the Game tab runs on `engine.speed_a_per_s` captured at `begin_game` — naturally satisfies "constant within a run"; a Setup change applies at the NEXT Start/Restart only.

## Recommended knob + rationale

**Choose (a): per-instance engine speed in Å/s (step size per tick) at the fixed 100 ms timer / dt = 0.1.**

1. (b) timer-interval knob is strictly more invasive: it changes sweep wall time (TURN_TICKS × interval), cooldown wall time, turn-application latency (the 04-09 "<1 s pause" observation was explicitly recorded as a SEPARATE cadence knob, not a speed knob — `04-09-SUMMARY.md:34,129,184`), and the spawn clock's "once per 100 ms movement tick" contract (`spawn.py:37,99-104,273-274`). Coupling all of that to a *difficulty* selector is wrong.
2. (a) keeps GAME-08 true by construction (one engine attribute, set once at `begin_game`, never mutated mid-run).
3. (a) keeps every Å-space collision/sweep/capture semantic identical per tick — only the per-tick displacement changes, which is precisely what "faster snake" means.
4. (c) both is unnecessary complexity; no requirement asks for cadence changes.
5. Confidence HIGH: this matches the engine's own design comment ("`dt` keeps engine determinism; cadence jitter is eaten by QTimer", `gui_game.py:86-87`) and the owner-amended contract changes nothing about time — time stays the QTimer's job.

Doc-comment maintenance implied by the choice: `game_engine.py:74-77` (placeholder note), `gui_game.py:83-87` (0.3 Å/tick hardcoded narrative), `game_engine.py:564-569` (step() docstring's 3.0 example) should be generalized to mention the tier injection.
