## Summary

- **The `speed` key ALREADY exists in the setup schema.** `setup_logic.DEFAULTS['speed'] = 3.0` (setup_logic.py:58), validated "number > 0" (setup_logic.py:203-205), and pinned by tests (tests/test_setup_logic.py:45, 149-164). It has been present since the module's first commit (3b7b8c0, plan 02-07). **No schema key needs to be invented** — GameEngine just never reads it yet.
- **The engine's speed is a module-level constant, not instance state.** `game_engine.SPEED_A_PER_S = 3.0` (game_engine.py:78) is consumed in exactly one place: `step()`'s movement branch (game_engine.py:640-641). `GameEngine.__init__`/`reset` take NO speed parameter (game_engine.py:247-258). ~104 test sites construct `GameEngine(...)` — the non-breaking seam is a new kwarg defaulting to `SPEED_A_PER_S`.
- **The Setup control precedent is `box_combo`: QComboBox + `addItem(label, userData)` + `currentData()`/`findData()`** (gui_setup.py:106-108, 240-242, 272-275). A speed-tier combo is a 1:1 copy of that pattern. No radio rows exist anywhere in the repo.
- **No Save/Load UI exists yet** (SETUP-07/08 are Phase 8; gui.py:78-79 has a reserved empty button row; 03-RESEARCH-setup-ui.md:237 says only the pure half exists). The persistence machinery that EXISTS is: (a) the anchored live dict `_serpentrum.setup` (__init__.py:25, 44-47) and (b) pure `save_setup`/`load_setup` JSON text round-trip (setup_logic.py:227-268). Success criterion 3 must be exercised at the pure layer; whether 5.1 pulls Save/Load BUTTONS forward from Phase 8 is a planner decision (see Open Questions Q1).
- **Backcompat is nearly free IF tier data rides the existing numeric `speed` key.** Every file `save_setup` ever wrote contains `speed` (default 3.0). `load_setup` does NO defaults-merge and `validate()` errors on a MISSING speed — so an absent-key scenario still needs a small merge helper, and Phase 5.2 will need the same helper (ROADMAP.md:189 requires "absent key = OFF" for its consent key). Build the merge once in 5.1.
- **GO! semantics are already GAME-08-correct by construction.** Start emits a snapshot (`collect_state()`) at GO! (gui_setup.py:553-563 → gui.py:84-94 → gui_game.py:347-423, 425-481); the live engine is built ONCE per begin_game and never re-reads setup. Mid-run combo changes write the anchor but cannot touch the running engine.
- **Restart re-reads the LIVE anchor dict, not the Start-time snapshot** (gui_game.py:1231, `_on_restart`). A combo change before Restart IS picked up — "Restart keeps the selection" (criterion 2) is satisfied by anchor semantics alone, provided `collect_state` writes the new speed value on combo change (it will, via the `_refresh_status` wiring pattern).
- **Side effect to flag:** `spawn.seed_from_setup` hashes the WHOLE setup dict via crc32 (spawn.py:117-129) — changing the tier changes the spawn seed, so Restart after a tier switch gives a *different but still deterministic* pickup sequence (same semantics as changing the box size).
- **Feel-check must be a human-verify checkpoint.** Headless widget construction is a proven dead end (01-05 decision; smoke/02_dialog_smoke.py is INFORMATIONAL-only). GUI verdicts = human checkpoints per 03-08 (10 steps), 04-09 (12 steps), 05-16 (8 steps across 7 live rounds). The per-tier script: select tier → Start → GO! → subjective verdict + wall-cross timing; plus Restart-keeps-tier and save/load round-trip steps.
- **Primary recommendation:** keep `speed` as the numeric Å/s value in the existing schema key; add `SPEED_TIERS` (ordered name→Å/s table) + `merge_defaults()` to `setup_logic.py` (PURE); add one `QGroupBox("Speed")` with a `box_combo`-pattern QComboBox to `gui_setup.py`; add one defaulted `speed_a_per_s` kwarg through `GameEngine.__init__/reset` (game_engine.py:247-275) consumed at game_engine.py:640-641; wire `setup.get('speed', ...)` at the single construction site `_build_engine` (gui_game.py:475-481); log the tier once per run via a new `hud_logic` builder following the `stack_mode_note` precedent.

## setup dict schema today

Defined in `serpentrum/setup_logic.py`; `DEFAULTS` at :49-59, `new_setup()` shallow-copies at :110-117.

| Key | Type | Default | Validation (setup_logic.py:148-224) |
|---|---|---|---|
| `schema_version` | int | 1 (`SCHEMA_VERSION`, :40) | must equal 1 (:174-177) |
| `demo_set` | str | `'set_a'` | must be in `KNOWN_SETS` (:179-182) |
| `head_molecule` | str | `'random'` | non-empty str (:211-214) |
| `box_preset` | str | `'medium'` | must be in `BOX_PRESETS` (:184-187) |
| `xtb_path` | str or None | `None` | None OK; else path rules via `_xtb_path_problems` (:199-201) |
| `win_cap_molecules` | int | 10 | number, 1..20 (:189-192); warns >10 (:219-222) |
| `atom_budget` | int | 100 | number ≥1 (:194-197); warns >100 (:220-222) |
| `broadening_fwhm` | float | 16.0 | number >0 (:207-209) |
| **`speed`** | **float** | **3.0** | **number >0 — already enforced (:203-205); bool rejected via `_is_number` (:120-124)** |

Key behavior facts:

- **No defaults-merge exists.** `load_setup` (setup_logic.py:242-268) validates ONLY `schema_version`, then returns the raw dict; a pinned test (`test_load_does_not_full_validate`, tests/test_setup_logic.py:322-327) locks this. Full validation is the CALLER's `validate()`.
- **Missing `speed` today → validate error.** `setup.get('speed')` → `None` → `"speed None must be a number > 0"` (setup_logic.py:203-205; never-raises contract tests at tests/test_setup_logic.py:253-255). So a setup file WITHOUT a speed key currently loads but fails validation → Apply would block. This is exactly the absent-key hole 5.1 (and 5.2) must close with an explicit merge.
- **`collect_state` preserves non-widget keys verbatim** by shallow-copying `self._setup` first (gui_setup.py:233): its own docstring lists `speed` as one of the preserved fields (gui_setup.py:229-231). Today that means an externally-loaded non-default speed survives the GUI; after the combo lands, `speed` moves from "preserved" to "widget-written" (same as `box_preset`).
- Unknown EXTRA keys in the dict are tolerated everywhere (validate ignores them; collect/apply shallow-copy carries them).

## Save/Load machinery + backcompat mechanics

**What exists (Phase 8 ships the UI):**

- `save_setup(setup) -> str` (setup_logic.py:227-239): validates first (errors → `SetupError`; warnings do NOT block), then `json.dumps(setup, sort_keys=True, indent=2)`.
- `load_setup(text) -> dict` (setup_logic.py:242-268): loud-fail `SetupError` on invalid JSON, non-dict payload, or `schema_version != 1`; then returns the raw dict.
- **No GUI Save/Load buttons.** The bottom row in gui.py:78-79 is reserved (comment "Phase 8: 6 right-aligned buttons"); Phase-8 research pinned QFileDialog wiring for SETUP-08 (03-RESEARCH-setup-ui.md:237). `grep save_setup` finds ZERO call sites outside setup_logic.py + tests.
- Test coverage to extend: `TestSaveLoadRoundTrip` (tests/test_setup_logic.py:262-297), `TestLoadSetupErrors` (300-327), `TestDefaults` (36-104 incl. `EXPECTED_DEFAULTS` pinning all 9 keys at :36-46 — **any DEFAULTS change breaks this test; any test change here is a visible, reviewable schema diff**).

**How backcompat works for each design:**

- **Numeric `speed` key (recommended):** every file ever written by `save_setup` already contains `speed` (the key was in DEFAULTS from the module's first commit, 3b7b8c0 → confirmed via `git log -S "'speed'"`): old files load at 3.0 = the "normal" tier with ZERO code change. The only un-covered case is a hand-edited/foreign file missing the key → needs the merge helper below.
- **Default-tier on absent key (required by criterion 3 + 5.2's "absent key = OFF"):** add a `merge_defaults(loaded)` helper in setup_logic.py — `dict(DEFAULTS)` overlayed with the loaded dict. Call it on the load path wherever the loaded dict enters live state (and re-use it in 5.2 for the consent key — 5.2's ROADMAP SC1 explicitly requires "absent key = OFF", ROADMAP.md:189). This is the ONE structural choice that makes 5.2's insertion cleaner: merge helper + a new `QGroupBox` (not editing an existing group) + collect_state's already-generic preserved-keys copy.
- **Do NOT bump `SCHEMA_VERSION`.** `load_setup` hard-rejects any version ≠ 1 (setup_logic.py:264-267); bumping would brick every existing file. The merge helper (not a version bump) is the backcompat mechanism — version stays 1.

## GO!/Restart speed-propagation trace

**GO! (Start):**
1. `SetupTab._on_start` → `_on_apply()`; on success emits `start_requested.emit(self.collect_state())` (gui_setup.py:553-563) — a FRESH snapshot including widget state.
2. `PluginDialog._on_start_requested(setup)`: switches to Game tab, calls `game_tab.begin_game(setup)` (gui.py:84-94).
3. `GameTab.begin_game(setup)` → `_build_engine(setup)` (gui_game.py:374, 425-481). Engine construction site is gui_game.py:475-481: `game_engine.GameEngine(..., cap=setup.get('win_cap_molecules'), atom_budget=setup.get('atom_budget'))` — **this is the single place `setup['speed']` must flow into the engine.**
4. Engine runs at fixed `TICK_DT = 0.1` / 100 ms QTimer (gui_game.py:88-89); movement per tick = `SPEED_A_PER_S * dt` (game_engine.py:640-641).

**Mid-run combo changes:** every widget signal funnels into `_refresh_status` → `collect_state()` → writes `self._anchor.setup` (gui_setup.py:335-345 → 225-254). The RUNNING engine is held in `self._session['engine']` and never re-reads setup → **GAME-08 (constant speed within a run) holds automatically**; no propagation code exists to break.

**Restart:** `_on_restart` reads `self._anchor.setup` (the LIVE dict) and re-runs `begin_game(setup)` (gui_game.py:1222-1236). So:
- A tier change followed by Restart (without Apply/Start) IS picked up — the anchor tracks the combo live.
- "Restart keeps the selection" (criterion 2) = anchor semantics, free once the combo writes `speed` in `collect_state`.
- **Determinism caveat:** `begin_game` reseeds the spawner with `spawn.seed_from_setup(setup)` (gui_game.py:465) = crc32 over ALL dict items (spawn.py:117-129). A tier change alters the seed → different deterministic pickup sequence on that run (identical semantics to changing box size; flag in the feel-check script so the owner isn't surprised).

**Engine-side seam (the only engine edit):** `GameEngine.__init__`/`reset` signatures (game_engine.py:247-275). All ~104 test call sites use `GameEngine(**ENGINE_ARGS)` or keyword args (tests/test_engine_core.py:62-129 etc.); adding `speed_a_per_s=SPEED_A_PER_S` as a trailing kwarg keeps every pin green, including `test_speed_constant_pinned` (tests/test_engine_core.py:85-87) which asserts the module constant stays 3.0. **Do NOT mutate the module constant at runtime** (module-global mutation is the Pitfall-7 anti-pattern the anchor discipline exists to kill). Sweep timing is tick-fixed (`TURN_TICKS = 6`, game_engine.py:86 → 0.6 s per turn regardless of tier) and the spawn-pool cooldown is tick-fixed (`EXHAUST_COOLDOWN_TICKS = 100`, spawn.py:101-104) — tiers change forward motion only; note this in the feel-check.

## Recommended selector design + rationale

1. **Schema (setup_logic.py, PURE):** keep `speed` numeric. Add `SPEED_TIERS = (('relaxed', 2.0), ('normal', 3.0), ('fast', 4.5), ('expert', 6.0))` (draft values; final at feel-check) and `merge_defaults(loaded)` (return `dict(DEFAULTS)` updated with loaded keys). Do NOT tighten `validate()` to tier-membership — keep "number > 0" (setup_logic.py:203-205) so hand-tuned speeds stay loadable; the combo is the UI constraint, not the schema. (If strictness is wanted later, it's an additive check.)
2. **UI (gui_setup.py, GUI):** new `QGroupBox('Speed')` + `QFormLayout` row `'Tier:'` + `speed_combo` populated from `SPEED_TIERS` with `addItem('%s (%.1f Å/s)' % (name, aps), aps)` — mirrors `box_combo` (gui_setup.py:106-108) exactly. `collect_state` reads `currentData()` into `setup['speed']` (parallel to gui_setup.py:240-242); `apply_state` `findData` with fallback to the default tier index (parallel to 266-270/277-281). Wire `currentIndexChanged` → `_refresh_status` (parallel to 210). Update the stale docstring line gui_setup.py:229-231 (speed moves from "preserved" to widget-written).
3. **Engine (game_engine.py, PURE):** trailing kwarg `speed_a_per_s=SPEED_A_PER_S` on `__init__`/`reset` (game_engine.py:247-275), stored on the instance, consumed at game_engine.py:640-641 in place of the module constant. Module constant stays 3.0 as the v1-default pin.
4. **Wiring (gui_game.py, GUI):** `_build_engine` passes `speed_a_per_s=setup.get('speed', 3.0)` (gui_game.py:475-481). One line at the single construction site.
5. **Surfacing (hud_logic.py, PURE):** `speed_note(tier_name, speed)` builder on the `stack_mode_note` pattern; logged once in `begin_game` next to gui_game.py:417-420. Resolve tier name from speed at log time (nearest/exact tier match, else `'custom'`).
6. **Backcompat:** `merge_defaults` applied wherever a loaded dict enters live state; unit test: `load_setup` a fixture JSON written WITHOUT `speed` → merged → validate clean → `speed == 3.0`. Keep `EXPECTED_DEFAULTS` (tests/test_setup_logic.py:36-46) unchanged — `speed: 3.0` already in it.
7. **Rationale:** minimal schema churn (existing key + existing validation + existing round-trip tests stay green), free old-file backcompat, Restart/GO! semantics need no new machinery (anchor + snapshot already correct), engine blast radius = one defaulted kwarg over ~104 call sites, and `merge_defaults` is the shared seam 5.2 needs for its "absent key = OFF" requirement (ROADMAP.md:189, 196).

## Open questions for planner

1. **Criterion 3's "Save Setup → Load Setup" mechanics — pure-layer only, or pull 2 buttons forward from Phase 8?** No Save/Load UI exists (gui.py:78-79 reserved row; 03-RESEARCH-setup-ui.md:237 defers wiring to Phase 8). Options: (a) exercise criterion 3 via `save_setup`/`load_setup` unit tests + anchor persistence, leaving GUI buttons in Phase 8 (smallest scope; the wiring is then trivial since the `speed` key is already in the schema); (b) add temporary Save/Load buttons to the Setup tab in 5.1 (violates the "Phase 8 owns SETUP-07/08" boundary but makes criterion 3 human-verifiable). **Recommend (a)**; needs owner/planner confirmation since the criterion text says "Save Setup → Load Setup".
2. **Speed value storage: numeric `speed` (existing key) vs. a new `speed_tier` string.** Research strongly favors numeric (free backcompat, zero schema churn); confirm at planning.
3. **`validate()` strictness:** keep "number > 0" (recommended — hand-tuned speeds stay legal) vs. reject non-tier values. Affects whether foreign/custom files survive validation.
4. **Default-tier index for foreign speeds in `apply_state`:** exact-match failure → select 'normal' (dict then normalizes on next `collect_state`), or add a transient 'custom (X Å/s)' display item. The existing fallbacks (demo→idx 0, head→Random) suggest 'normal' is the house pattern.
5. **Final tier values + names:** drafts 2.0/3.0/4.5/6.0 Å/s (ROADMAP.md:181) are owner-finalized at the feel-check — the plan should pin the checkpoint structure but leave values as one-edited-line constants in `SPEED_TIERS`.
6. **HUD speed line: yes/no.** Recommend the once-per-run `speed_note` log line (cheap, pure, precedent-matching); confirm scope.
7. **5.1 vs 5.2 sequencing note:** STATE.md says execute 5.2 → 5.1 (shared gui_setup/hud_logic); ROADMAP.md:196 agrees. If 5.2 lands first, `merge_defaults` may already exist under 5.2 ownership — planner should coordinate which phase owns the helper to avoid double-adding it.
