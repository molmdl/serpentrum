Load-bearing facts (03-RESEARCH-upload-gate.md; trust over memory):
- Ring count = cyclomatic number mu = E - V + C (circuit rank; equals SSSR count for normal organics). Computed from the bond graph: V = atom count, E = len(bonds), C = connected components via BFS/union-find on adjacency. Verified demo math: benzene 1, naphthalene 2, anthracene 3, phenanthrene 3, biphenyl 2. H atoms are pendant (net-zero effect on mu).
- Charge: SDF formal charges survive via `M  CHG` records (PITFALLS 11, [SRC: chempy/mol.py:74-81]); sum ALL values across ALL M CHG lines; absent -> 0. mol2 carries PARTIAL charges only ([SRC: chempy/mol2.py:74]) -> formal charge assumed 0 + warning text 'mol2 does not preserve formal charges; charge assumed 0. Use SDF for ionic species.'
- Explicit-H gate (PITFALLS 11a; do NOT auto-add H, cmd.h_add banned): organic (contains C, N or O) + zero H -> REJECT; organic with H -> accept; inorganic (no C/N/O) + zero H -> WARN but accept ('no hydrogens — verify this is correct for an inorganic molecule'); any molecule with H -> accept.
- Ring gate: mu <= 3 else reject with reason '<name>: has <mu> rings (limit is 3)'. Charge is INFORMATION, never a rejection.
- Error contract: mirror xyzio.py — MolFileError(ValueError) naming the 1-based line number and quoting the first ~60 chars of the offending line (xyzio.py:63-78 pattern; reuse the _line_error shape, _SNIPPET_MAX = 60).
- Element symbols validated CASE-SENSITIVELY against xyzio.ELEMENT_SYMBOLS (intra-package relative import — purity-exempt).
- SDF V2000 details are [TRAIN]: counts line 'aaabbb...V2000' (aaa = natoms, bbb = nbonds, 3-char fields; whitespace-split fallback per research §12.1); atom rows x/y/z then element symbol (try whitespace tokens[3]; fallback fixed slice cols 31:34); bond rows '111222ttt' (first two 3-char fields, whitespace fallback); 'M  CHG' lines: strip the 'M  CHG' prefix, first token = pair count, then count (index, charge) pairs. Split records on lines whose strip() == '$$$$'. The post-checkpoint real-PubChem regression test (plan 03-05) closes the format gap.
- Molecule record contract (03-RESEARCH-upload-gate.md §4.1) — DEVIATION APPROVED at planning: parsed records ALSO carry 'coords' (list of (x,y,z) float tuples) and 'charges' (dict {0-based atom index: int formal charge}); research said coords stay off the record, but the Phase-3 upload split (03-04) must re-serialize accepted single records, which needs coords + per-atom charges. Downstream engine/bridge geometry still comes from PyMOL objects (cmd.load), never from records — the single-source-of-truth rule is unchanged.
- Gate output contract: gate_molecule(record) -> (ok: bool, reason: str|None); advisories live on record['warnings'] (list of str; mol2 charge note, inorganic no-H note). gate_set(records) -> (accepted: [record], rejected: [(record, reason)]).
- Hard conventions: python3.6 only (%-formatting, no dataclasses/walrus/f-string =); stdlib only; purity checker auto-classifies new serpentrum/ modules PURE (bans pymol/pmg_tk/PyQt5/numpy even in function bodies); tests zero sys.modules stubs; discovery = `python3.6 -m unittest discover -s tests -p "test_*.py" -v` (never `-t .`); tests/fixtures/molfile/ gets NO __init__.py (plugin-path safety); every test file repeats the sys.path self-insert preamble.
- Wave-1 parallelism: do NOT import other Phase-3 modules (setloader/pymol_bridge do not exist yet); this plan is fully self-contained (stdlib + serpentrum.xyzio).

    serpentrum/molfile.py — stdlib only (no imports needed beyond maybe nothing; adjacency BFS with sets/lists). %-formatting. Public surface:
    - MolFileError(ValueError) + _line_error(lineno, text, message) helper (mirror xyzio.py:63-78, _SNIPPET_MAX = 60).
    - count_rings(bonds, atom_count) -> int: adjacency sets; BFS/iterative component count; mu = len(bonds) - atom_count + components. bonds are (i, j) 0-based pairs.
    - read_sdf_text(text) -> [record]: split on '$$$$' lines; per record: title = line 1, skip lines 2-3, counts line (fixed 3-char slices with whitespace-split fallback), atom rows (coords = first 3 floats; element = whitespace token 3, fallback fixed slice [31:34]; validate against xyzio.ELEMENT_SYMBOLS case-sensitively via _line_error on failure), bond rows (first two 3-char fields / whitespace fallback, 1-based -> 0-based), 'M  CHG' property lines (strip prefix, token pairs) accumulated into charges dict. Every int()/float() conversion and structural violation wrapped -> MolFileError with 1-based line + snippet.
    - read_sdf(path): open(path, encoding='utf-8'), delegate.
    - write_sdf_text(record) -> str: V2000 fixed-width serialization ('%3d%3d  0  0  0  0  0  0  0  0999 V2000' counts; '%10.4f%10.4f%10.4f %-3s 0 ...' atoms; '%3d%3d%3d  0' bonds; M CHG lines emitted from record['charges'] when non-empty, <= 8 pairs per line) ending with '$$$$'.
    - read_mol2_text(text) -> [record]: @<TRIPOS>MOLECULE (name), @<TRIPOS>ATOM rows (id, name, x, y, z, ...), @<TRIPOS>BOND rows (id, a1, a2, ...). charge = 0, charges = {}, warnings = [mol2-charge text]. Same MolFileError contract with 1-based line numbers.
    - read_mol2(path): file wrapper.
    - find_ring_atoms(record) -> list: shortest-cycle-through-atom BFS over the CARBON subgraph (or any-element subgraph — for the demo/gate scope a BFS shortest cycle over all atoms starting from each atom, first cycle of length >= 3 found, returned sorted; cap search to avoid pathological cost). Returns [] when acyclic.
    - gate_molecule(record) -> (ok, reason): checks IN ORDER — (a) ring_count > 3 -> reason '<name>: has <n> rings (limit is 3)'; (b) organic (any of C/N/O in elements) and not has_explicit_h -> reason '<name>: no explicit hydrogens found — provide a pre-protonated file (auto-H is not used per policy)'; (c) inorganic (no C/N/O) and not has_explicit_h -> append hydrogen advisory to record['warnings'], accept. Charge never rejects.
    - gate_set(records) -> (accepted, rejected): apply gate_molecule in order; rejected = [(record, reason)].
    Explicitly OUT of scope: setloader (03-04), any pymol import (PURE module), manifest handling (molecule_data owns it).
