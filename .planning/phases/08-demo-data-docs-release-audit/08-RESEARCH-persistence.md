## Summary

The pure persistence machinery for SETUP-08 **already exists and is fully unit-tested**: `setup_logic.save_setup` (sorted-key indented JSON, validate-first), `load_setup` (loud `SetupError` on corrupt JSON / non-dict / foreign schema_version), `merge_defaults` (absent-key overlay — the 5.1-02 SC3 seam), and `randomize_head` (private `random.Random(seed)`, never the global module). Phase 8's job is **GUI wiring + friendly-error wrapping + two small new pure helpers** (a randomize-setup function, and a load-normalization policy for environment-specific keys). The canonical bottom row is the **reserved empty `QHBoxLayout` in `gui.py:129-130`** (`addStretch(1)` first = right-aligned, per the comment "Phase 8: 6 right-aligned buttons"); the three temp buttons in `gui_setup.py` are **replaced**, not moved. The `04-06` decision's "Phase-8 bottom row **byte-identical**" constrains the **Start route** (apply-first `_on_apply` bool contract → `start_requested(setup)` → dialog-owned `setCurrentIndex(1)`), not the button count.

The core SETUP-08 design decision is the **per-key reproducibility classification** below: 7 of 10 keys reproduce byte-exact on a fresh install (demo data ships in `serpentrum/data/`; spawns are crc32-deterministic over the whole dict); `xtb_path` is the one environment-specific key needing a normalize-on-load policy; upload-derived `head_molecule` ids and the current head-combo selection are the only irreproducible values, both handled gracefully by existing `apply_state` fallbacks.

**Primary recommendation:** keep the 6-button row in `PluginDialog` (spec: bottom of the window, not a tab), route all six buttons to `SetupTab` handlers, keep the Start/emit route byte-identical per 04-06, add pure helpers `randomize_setup(...)` + load normalization in `setup_logic.py` (TDD-able), wrap `SetupError`/`IOError` in the established friendly surfaces (status label + static `QMessageBox.warning`), and pause active gameplay before opening any modal from the bottom row (PITFALLS.md Pitfall 5 — the row is visible on the Game tab mid-run).

## Q2 — Save/Load file UX design space

### Precedents (all HIGH confidence, read from live tree)
- **`QFileDialog.getOpenFileName`**: `gui_setup.py:436-449` (two browse handlers: upload molecules `*.sdf *.mol2`, xtb exe). Returns `(path, filter)`; cancel = empty path, guard `if path:`.
- **`QFileDialog.getSaveFileName`**: `gui_plot.py:486-491` (`_on_save`): filter `'PNG image (*.png)'`, **`endswith` check + extension append** at `:490-491` — copy this pattern for `.json`.
- **Purity**: static conveniences carry no `.exec_()` token → AST gate clean (03-RESEARCH-setup-ui.md:29-31; `tools/check_purity.py:200-207` bans only the `exec_` attribute call). `.exec_()` is banned in **every** module class; the row must never introduce one. Prior GUI audits pin `grep -c 'exec_' == 0` (07-07-PLAN verify).
- **Error surfacing split** (`gui_setup.py:14-21` docstring): one-shot blocking errors → static `QMessageBox.warning(self, title, body)` (`:507-509`, `:517-520`, `:616-618`); persistent/advisory → the **status label** (`:153-154`) or the inline hessian-style QLabel (`:127-130`). The load-corrupt case maps to QMessageBox (one-shot) AND status label (persistent) — the exact `_on_apply` double-surface precedent (`:507-509` + `:509`).

### What `save_setup` / `load_setup` do today
- `save_setup(setup) -> str` (`setup_logic.py:313-325`): **validates first** — errors raise `SetupError`; warnings (hessian) do NOT block. Serializes the FULL dict including `schema_version` as sorted-key indented JSON. Live-validated GUI state should never raise, but the `SetupError` catch is still required (hand-state drift).
- `load_setup(text) -> dict` (`:328-354`): `SetupError` on invalid JSON / non-dict payload / `schema_version != 1`; **no merge, no full validation** (pinned by `test_load_does_not_full_validate`, tests/test_setup_logic.py `TestLoadSetupErrors`).
- **The Phase-8 wrap contract is written into the code**: `setup_logic.py:13-14` ("NOT in this plan: ... friendly corrupt-file UX (SETUP-08) — v1 `load_setup` raises loudly; Phase 8 wraps it") and `SetupError` docstring `:138-141`. **Wrap lives in the GUI layer (`gui_setup` handlers); `setup_logic` stays loud.** Do not soften the exceptions — tests pin them.

### Recommended Load flow (per handler, in `__init__);
1. `getOpenFileName(self, 'Load setup', '', 'serpentrum setup (*.json);;All Files (*)')`; cancel guard.
2. Read text, catching `IOError`/`OSError` → friendly status.
3. `setup_logic.load_setup(text)` — catch `SetupError` → `QMessageBox.warning('Cannot load setup', ...)` + status label (the `_on_apply` double-surface).
4. **`merge_defaults(loaded)`** — REQUIRED for absent-key tolerance (`setup_logic.py:154-172`; "Applied by CALLERS after `load_setup`... pinned by `test_load_does_not_full_validate`"). Loads written before `speed`/`generic_stack_consent` existed must not error.
5. **Normalize environment-specific keys** (Q3 below — the design decision).
6. `validate(merged)` → errors surface exactly like `_on_apply`'s validate branch (`:506-510`); a friendly note may help identify which key failed.
7. Success: `apply_state(merged)` (its fallbacks handle unknown demo_set `:316-320`, unknown head id `:345-349` → Random, foreign speed `:330-336` → default tier) **and write the anchor** (`collect_state` writes `self._anchor.setup` at `:302-303` — call it or assign directly; reload-survival requires the anchor write, decision 03-07 / STATE.md:73).

### Recommended Save flow
1. `collect_state()` (current widget state; writes anchor) → `save_setup` (catch `SetupError`).
2. `getSaveFileName(self, 'Save setup', '', 'serpentrum setup (*.json)')` + `.json` extension append (`gui_plot.py:490-491` pattern).
3. Write text; `IOError` → friendly status.
4. Filename default: none in the codebase — house precedent is empty default dir (browse `:438-440`, plot `:487`). Suggest a proposed name (e.g. `serpentrum_setup.json`) as a small UX add — Q-Open 5.

## Common pitfalls

### Pitfall A: `collect_state` preserved-keys defeats naive Reset
**What goes wrong:** `collect_state` shallow-copies `self._setup` first (`gui_setup.py:279`) and preserves non-widget keys (`schema_version`, `atom_budget`, `broadening_fwhm` — docstring `:273-277`). A Reset implemented only as `apply_state(new_setup())` leaves the OLD `atom_budget`/`broadening_fwhm` in the dict after the next collect.
**Avoid:** explicit assignment (`self._setup = setup_logic.new_setup()` + anchor write) BEFORE/instead of relying on collect.

### Pitfall B: modal file dialog during active gameplay (PITFALLS.md Pitfall 5)
**What goes wrong:** the bottom row is visible while the **Game tab's 100 ms tick timer runs**; Save/Load open modal QFileDialog statics; PITFALLS.md:134 bans modals during gameplay without pause; tick coalescing + wall-clock elapsed inflation follow.
**Avoid:** bottom-row modal handlers must call `game_tab.request_auto_pause()` first (the existing focusInEvent safety-net precedent `gui.py:333-345`) — or disable Save/Load while status == 'playing'. `request_auto_pause` already guards on status, so calling it unconditionally is safe.

### Pitfall C: SetupError paths not wrapped
**What goes wrong:** `save_setup` raises on invalid state; `load_setup` raises on corrupt/non-dict/foreign-version; file `IOError` on permission/missing paths. Unwrapped → uncaught exception in a slot → PyMOL console noise, no UI signal.
**Avoid:** narrow `try/except (SetupError, IOError)` per handler → `QMessageBox.warning` + status label (the `_on_apply` double-surface).

### Pitfall D: Randomize writes `'random'` back → SETUP-08 reproduction silently lies
**What goes wrong:** if Randomize leaves `head_molecule='random'`, the saved file cannot reproduce the head the user saw. (Today `'random'`→`records[0]` deterministically — see Q-Open 1 — but any future true-randomization would break reproduction.)
**Avoid:** Randomize writes **concrete** values (chosen id, presets) into the dict.

### Pitfall E: anchor write forgotten on Load
**What goes wrong:** `apply_state(loaded)` updates widgets but not `self._anchor.setup`; the Game tab's Restart reads the ANCHOR (`gui_game.py` `_on_restart`), and plugin reload loses the loaded config (decision 03-07, `__init__.py:65` initializes only on first anchor).
**Avoid:** conclude the load with `collect_state()` (writes anchor `:302-303`) or a direct anchor assignment.

### Pitfall F: `.pse` desync (PITFALLS.md F8 / Pitfall 8.3)
**Context, not a new trap:** Cleanup model is THE recovery path for orphaned `srp_*` objects after a session reload; it works in a fresh process by name-prefix (`pymol_bridge.cleanup_srp`, INFRA-04). Keep it reachable from the bottom row on **every** tab (don't gate it on Setup-tab context) — it is dialog-scope, not tab-state.

### Pitfall G: unknown extra keys pass through silently
`merge_defaults` tolerates unknown keys (docstring `:161-162`); `validate` ignores them. A hand-edited file with typos loads "successfully" with the typo'd key silently ignored and defaults used. Advisory (not error): the status line can mention ignored extras if desired — defer (nice-to-have).
