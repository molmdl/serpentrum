Load-bearing design facts:
- **Where shipped data files will live (NOT this plan's files):** `serpentrum/data/demos/manifest.json` + `serpentrum/data/demos/stacking.json`. `serpentrum/` is itself the plugin package; data files are not `.py`, so they are invisible to the purity walk AND to findPlugins. Tests here must NOT create them — build synthetic files in `tempfile.mkdtemp()` tmpdirs instead (keeps committed data pristine and exercises error paths). A later plan (demo-data prep / integration) creates the shipped files using THIS schema; the demo-data research's §6 content (fields mode_id/distance/citation-list) maps into this schema at data-prep WITHOUT altering numbers.
- **Validation is structural only:** citation key must RESOLVE in citations; `approved` is data, not a loader opinion. Do not validate chemistry truth.
- **Error format (research literal example):** `DataError("stacking.json interaction 0: missing key 'distance_a'")` — pattern: `'<file basename> <entry kind> <index>: <problem>'`.
- **py3.6 bool-is-int trap:** `isinstance(True, int)` is True — integer validators must reject bools explicitly (`isinstance(x, int) and not isinstance(x, bool)`), or `atom_count: true` would validate.
- **Hard conventions:** Python 3.6 (%-formatting, no dataclasses/walrus); stdlib json/os only; purity auto-classifies PURE; zero sys.modules stubs.
- **Wave-1 parallelism:** do NOT import other Phase-2 modules. This plan is fully self-contained (json/os + tmpdirs).
- **Test conventions:** discovery = `python3.6 -m unittest discover -s tests -p "test_*.py" -v` (never `-t .`); tests/ has NO `__init__.py`; sys.path self-insert preamble in every test file; cleanup tmpdirs with shutil.rmtree in addCleanup (shell `rm` denied).
