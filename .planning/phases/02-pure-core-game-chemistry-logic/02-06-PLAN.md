Pinned design (research R7 + planner decisions — implement EXACTLY this):
- **Constants (module-level, documented):** SPEED_A_PER_S = 3.0 (GAME-08; exact value = Phase-4 playtesting); TURN_DEGREES = 90.0; TURN_TICKS = 6 (sweep completes in 6 step() calls; animation polish is Phase 5); BODY_COLLISION_RADIUS_A = 2.0 (MUST stay < stacking distance 3.4 minus margin, else the head "collides" with the segment just stacked); SEGMENT_SKIP_RECENT = 2 (exclude the last N segments from self-collision); PICKUP_RADIUS_A = 3.0; HEAD_WALL_MARGIN_A = 1.0 (= BODY_COLLISION_RADIUS_A/2 — the planner decision for research's open margin item); SWEEP_PICKUP_CLEARANCE_A = 2.5 (same rationale as stacking's clash threshold).
- **Coordinate model:** continuous 2D floats in the box's xy-plane; z is display-only and carried but never rotated. Directions are the 4 axis names {'left','up','right','down'} mapping to unit vectors right=(1,0), up=(0,1), left=(-1,0), down=(0,-1). Heading angles (math convention, CCW positive): right=0, up=+90, left=180, down=-90.
- **Segment list order:** index 0 = OLDEST (tail-most), LAST = most recently stacked (nearest the head); new stacks APPEND at the end. Self-collision checks cover segments[:max(0, len(segments) - SEGMENT_SKIP_RECENT)] — the two nearest the head are always skipped (they sit within pickup radius of it).
- **step(dt) contract:** paused or finished -> return [] immediately. If not sweeping and a direction is pending: pop it, run the sweep pre-check; on refusal emit ('turn_refused', reason) and CONTINUE with the forward move this tick (state-unchanged rule for the sweep itself); on success open the sweep AND advance it one tick in this same step (no forward move when sweeping). Sweep tick: rotate the whole chain rigidly about the head to angle theta_k = start + (target - start) * tick / TURN_TICKS, emit ('turning', tick / TURN_TICKS); when tick reaches TURN_TICKS: heading = target_heading, sweeping = None (the NEXT step resumes forward motion on the new heading — the head itself is the pivot and does NOT move during a sweep). Forward branch order: ('moved', (x, y)) -> boundary check -> body check -> pickup capture -> win check. Boundary/body hit: finished=True, result='crashed', emit ('crashed', 'boundary'|'body'), return immediately (no pickup check that tick).
- **Boundary:** crash iff head.x <= box_min[0] + HEAD_WALL_MARGIN_A or head.x >= box_max[0] - HEAD_WALL_MARGIN_A or the same for y (equality triggers).
- **Body:** for each checked segment, for each atom: 2D distance from head to the atom's (x, y) < BODY_COLLISION_RADIUS_A -> crash. (v1 simplification of GAME-05's "head-centroid vs chain segments": per-atom spheres approximate the segment capsule; refinement is Phase 5 if playtesting demands.)
- **Pickup capture:** for each live pickup with engaged == False: 2D distance(head, pickup['centroid']) <= PICKUP_RADIUS_A -> mark engaged, emit ('stacked', pickup). The CONTROLLER (Phase 5) then runs stacking.place_pickup + check_clash and calls attach_segment or reject_pickup. reject_pickup re-arms the pickup (engaged=False) — re-fire while the head remains in radius is possible and accepted in v1 (deterministic; tuning is Phase 5).
- **Sweep refusal pre-check (GAME-10, BEFORE any mutation):** sample k = 0..TURN_TICKS (TURN_TICKS+1 = 7 angles) of the WHOLE chain rotated rigidly about the head; at every sample: (a) any rotated chain atom outside [box_min, box_max] (inclusive bounds) -> refuse 'boundary'; (b) any rotated chain atom within SWEEP_PICKUP_CLEARANCE_A (2.5) of any live pickup atom -> refuse 'pickup'. NO body-vs-body check is needed: rigid rotation is an isometry (preserves all pairwise distances), so the rotated chain cannot self-collide if it did not before — the only movable-vs-static pairs are chain-vs-walls and chain-vs-pickups. Document this reasoning in the code. The sampled-arc approximation (positions BETWEEN samples unchecked) is accepted in v1; more samples = Phase 5 tuning. The refused request is consumed (pending emptied) — the player re-requests.
- **request_direction(d):** invalid name -> ValueError. Reference heading = sweeping['target_heading'] if sweeping else current heading. dot(d_vec, reference) < -0.5 -> ignored (180, locked); dot > 0.5 -> ignored (same direction); len(pending) >= 1 -> ignored (buffer full, "max 1 buffered beyond current"); else buffer and return True (ignored cases return False).
- **attach_segment(molecule_id, centroid, atoms):** append {'molecule_id', 'centroid', 'atoms', 'atoms_n': len(atoms)} to segments; molecules_stacked += 1; atoms_total += len(atoms); remove the pickup whose id == molecule_id from the live list; update pickups_remaining. (Stacked molecules are FROZEN rigid bodies — GAME-10 invariant; rendering maps atoms from engine truth.)
- **reject_pickup(pickup):** refusal_counts[pickup['id']] += 1; pickup['engaged'] = False; pickup stays live. Returns the event tuple ('refused', pickup['id']) for the controller to log (engine methods outside step() cannot emit onto step's event list).
- **Constructor:** GameEngine(box_min, box_max, head=(0.0, 0.0), heading='right', cap=10, pickups=None, segments=None). box_min/box_max are 2-tuples (engine logic is xy-only). pickups/segments: lists of the dict shapes above — the segments parameter is an explicit TEST SEAM (production chains grow via attach_segment). The engine copies pickup/segment dicts (never mutates caller data) and adds pickup['engaged'] = False. State also: pending (max-1 buffer), sweeping (None or {'start_heading','target_heading','tick'}), molecules_stacked, atoms_total, pickups_remaining, refusal_counts, paused, finished, result.
- **reset(...):** same parameters as __init__; rebuilds ALL state (GAME-07 restart).
- **Win:** at the end of the forward branch, if molecules_stacked >= cap and result is None -> finished=True, result='won', emit ('won',). (Cap = target count; GAME-06's "exceeds" is interpreted as "reaches" per the engine spec — the info box counts molecules-remaining down to 0.)
- **Determinism:** pure float math, fixed sample counts, NO RNG, NO wall-clock (pause timing is the GUI's job — Pitfall 9.3).
- **Hard conventions:** Python 3.6 syntax only (%-formatting, no dataclasses/walrus/f-string `=`); stdlib math/collections only; purity auto-classifies PURE (no pymol/Qt/numpy anywhere, function bodies included); zero sys.modules stubs.
- **Wave-1 parallelism:** do NOT import other Phase-2 modules (stacking/setup_logic do not exist in your worktree yet) — the stacking controller integration is Phase 5; this plan is self-contained.
