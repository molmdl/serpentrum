**Checker contract — module classification** (relative paths, posix, from the repo root):
- `serpentrum/__init__.py` → ENTRY
- `serpentrum/gui.py` → GUI (explicit allowlist set at top of file: `GUI_MODULES = {'serpentrum/gui.py'}` with comment "extend consciously in later phases — a new GUI module must be added here deliberately")

**Checker contract — rules** (banned root modules: `pymol`, `pmg_tk`, `PyQt5`, `numpy`; root = first segment of `ImportFrom.module`, or of each `Import` alias name; relative imports — `ImportFrom` with `module=None`/`level>0` — are intra-package and always exempt):

| Module class | pymol / pmg_tk | PyQt5 | numpy | .exec_() calls |
|---|---|---|---|---|
| ENTRY | allowed ONLY inside function/method bodies (lazy); module level → violation | never (anywhere) | never (anywhere) | violation |
| GUI (allowlist) | ONLY `pymol.Qt` / `pymol.Qt.*` forms (module level or bodies); any other pymol*/pmg_tk anywhere → violation | never | never | violation |
| PURE | never (module level or bodies) | never | never | violation |

Additional rules:
- `.exec_()` gate: walk all `Call` nodes; `func` is an `Attribute` with `attr == 'exec_'` → violation with file:line. (Phase 1: no child dialogs exist, so zero allowed; later phases add an explicit per-module allowlist.)
- PyQt5 and numpy are implied banned everywhere by the table (no allowance ever grants them).
- Docstrings/comments are AST-invisible → mentions like "from PyQt5 import" in text are NOT violations (this is why AST beats grep).

**Implementation notes (research-verified gotchas):**
- Module-level check: iterate `tree.body` direct children only (never `ast.walk` for this rule).
- Anywhere check: `ast.walk(tree)`, flag every `Import`/`ImportFrom` whose root is banned per the module's class.
- Violations accumulate as `(rel_path, lineno, message)`; `check_tree(root)` returns the list; `main()` prints `rel:line: message` and exits 1 on any violation, 0 clean. CLI: `python3.6 tools/check_purity.py [root]` (default: repo root, i.e. parent of tools/).
- Only files under `<root>/serpentrum/` are checked (dev-side tests/tools/smoke are not plugin modules).

`tests/test_purity_gates.py` self-test (build fixture trees under `tempfile.mkdtemp()` mirroring the `serpentrum/` layout; clean up with `shutil.rmtree` in `addCleanup` — never shell `rm`; opencode.json denies it):

2. pure module whose DOCSTRING contains the literal text `from PyQt5 import QtWidgets` → clean (no false positive)
3. ENTRY with `from pymol import cmd` at module level → violation ("module level")
4. ENTRY with lazy `from pymol.plugins import addmenuitemqt` + `import pmg_tk.startup` inside function bodies → clean
5. GUI with module-level `from pymol.Qt import QtWidgets` → clean
6. GUI with `from pymol import cmd` (any level) → violation (allowlist is pymol.Qt only)
7. any module with `from PyQt5 import QtWidgets` → violation
8. any module calling `d.exec_()` → violation with file:line
9. relative import `from .gui import PluginDialog` inside a function → clean
